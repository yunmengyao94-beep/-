# 数据字典 · 前端枚举

> 用途：前端渲染下拉框、标签、筛选器时，**只认这份字典**，不要在页面里写死中文。
> 同步源：`frontend/utils/constants.js`（本文件与代码常量必须一一对应，改一处要改两处）。
> 依据：计划书 6.3.2（`biz_item.category`）、6.3.3（`biz_order.state`）。

## 1. category · 物品类目

对应字段：`biz_item.category`（VARCHAR(30)）

| 枚举值    | 中文 | 说明                             | 前端用途           |
| --------- | ---- | -------------------------------- | ------------------ |
| `apparel` | 服饰 | 学士服、正装、假发、汉服等       | 类目筛选、卡片角标 |
| `digital` | 数码 | 相机、平板、电脑、镜头等高值设备 | 类目筛选、高值提示 |
| `tool`    | 工具 | 电钻、螺丝刀、卷尺等五金工具     | 类目筛选           |
| `other`   | 其他 | 雨伞、行李箱、帐篷等生活用品     | 类目筛选、兜底展示 |

### 补充说明

- **高值类目**：`digital`、`wig`（假发）、`formal_wear`（正装）受 5.4.1 / 5.4.5 的借用限制约束，
  与 `is_high_value = 1` 标记配合使用；类目本身不等于高值判定。
- **数据现状差异**：`server/seed_db.json` 中另有 5 条 `teaching_aid`（教具——显微镜、化学实验箱等），
  该值来自 6.3.2 的「教具」类目，但不在本次约定的 4 个枚举内。
  前端在 `constants.js` 中以 `CATEGORY_EXTRA` 单独承载，映射为「教具」，
  待产品确认后决定是并入正式枚举还是迁移数据。
- **未知值兜底**：任何未命中的类目一律显示「其他」，不允许出现空白或 `undefined`。

## 2. order_state · 订单状态

对应字段：`biz_order.state`（TINYINT）

| 枚举值 | 中文   | 说明                              | 前端用途                   |
| ------ | ------ | --------------------------------- | -------------------------- |
| `0`    | 待交接 | 已下单，等待双方扫码/视频验货交接 | 订单卡片主状态、倒计时提醒 |
| `1`    | 使用中 | 已完成交接存证，物品在借用者手中  | 归还入口、逾期红点         |
| `2`    | 已完成 | 已归还并确认无损，押金分已解冻    | 可评价、可再次借用         |
| `3`    | 仲裁中 | 出借者发起定损，进入仲裁流程      | 置灰不可操作、展示仲裁进度 |

### 补充说明

- **补充状态**：6.3.3 还定义了 `4` = 已取消（超时未交接或主动取消），
  当前 演示流程未产生该状态，前端以 `ORDER_STATE_EXTRA` 承载，映射为「已取消」，
  展示为灰色标签、不提供操作入口。
- **状态与操作映射**（建议）：`0` → 交接、取消；`1` → 归还、申请延期；
  `2` → 评价、再次借用；`3` → 仅查看；`4` → 仅查看。

## 3. 使用方式

```js
import { CATEGORY, ORDER_STATE, categoryLabel, orderStateLabel } from './utils/constants.js';

categoryLabel('digital'); // '数码'
categoryLabel('teaching_aid'); // '教具'（走扩展字典）
categoryLabel('unknown-value'); // '其他'（兜底）

orderStateLabel(1); // '使用中'
orderStateLabel(4); // '已取消'（走扩展字典）

// 渲染下拉框可直接用列表常量
CATEGORY_LIST.forEach(({ value, label }) => {
  /* <option value=...>label</option> */
});
```

## 4. 维护约定

1. 新增枚举值必须同时改：`docs/data_dictionary.md`、`frontend/utils/constants.js`、`server/seed_db.json`。
2. 中文标签变更视为**接口契约变更**，需在群里同步前后端与测试。
3. 枚举值一律小写下划线（`teaching_aid`）或整数，禁止用中文作为取值。
