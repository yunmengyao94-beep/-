# 离线（断网）冒烟测试 · 首页

> 目的：验证首页在接口不可达时**不白屏**，而是给出全局错误提示 + 可重试的错误态。
> 适用：Sprint 4 首页 `frontend/index.html`。

## 前置条件

1. Mock 服务已启动：`npm run server`（默认 `http://localhost:3000`）
2. 用静态服务打开首页（**不要用 `file://` 直接双击**，ES Module 会被 CORS 拦截）：
   - 方式 A：直接访问 `http://localhost:3000/index.html`（Mock 服务已托管 `frontend/`）
   - 方式 B：VS Code Live Server 打开 `frontend/index.html`

## 测试步骤（Chrome / Edge）

| #   | 操作                                                          | 预期结果                                                                          |
| --- | ------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 1   | 打开首页，确认列表正常加载出卡片                              | 首屏先出现 6 张骨架卡片，随后替换为真实物品                                       |
| 2   | `F12` 打开 DevTools → Network 面板 → 勾选 `Offline`（无网络） | 面板顶部出现离线标识                                                              |
| 3   | `Ctrl + R` 强制刷新页面                                       | 骨架屏短暂出现后消失，**页面不白屏**：顶部导航、搜索框、筛选按钮、底部标签栏仍在  |
| 4   | 观察页面中部                                                  | 出现全局错误 Toast（红色，文案以「加载失败：」开头），右上角关闭或 3 秒后自动消失 |
| 5   | 观察列表区域                                                  | 展示错误态：⚠️ 图标 +「物品加载失败」+ 错误原因 + **「重新加载」按钮**            |
| 6   | 观察右上角条数                                                | 显示「加载失败」                                                                  |
| 7   | 取消勾选 `Offline`，点击「重新加载」                          | 错误态消失，骨架屏 → 列表恢复正常，Toast 可再次出现「已加载」相关提示             |

## 判定标准（全部满足才算通过）

- [ ] 断网刷新后**没有白屏**，导航 / 搜索 / 标签栏等静态部分照常可见
- [ ] 出现**全局**错误提示（Toast）
- [ ] 列表区有**局部**错误态与可点击的「重新加载」按钮
- [ ] 恢复网络后点击重试能**自愈**，无需刷新页面

## 自动化替代验证

无浏览器环境时，可用 Node + 最小 DOM 桩对 `frontend/js/index.js` 做等价验证：
把 `globalThis.fetch` 置为 `reject`，断言

1. `#item-grid` 被加上 `hidden`；
2. 页面出现 `.empty-state` 且文案包含「物品加载失败」；
3. 存在 `.btn` 且文案为「重新加载」；
4. `#result-count` 为「加载失败」；
5. 恢复 `fetch` 后点击该按钮，网格重新出现卡片、错误态被移除。

本仓库 Sprint 4 Batch 4 交付时即用该方式回归通过（9 项断言）。

## 已知边界

- 离线只影响**接口请求**；页面本身的 HTML/CSS/JS 由静态服务器提供，若静态服务器也不可用则页面无法加载，属另一类故障。
- Service Worker 尚未接入，因此离线时没有"缓存兜底"数据；后续如需离线可用，应加 SW + 缓存首屏静态资源，并给接口做 stale-while-revalidate。
